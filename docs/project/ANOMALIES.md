# NEXORA — Anomaly Register

## Severity

- CRITICAL — release blocker.
- HIGH — major functional/security problem.
- MEDIUM — significant defect with workaround.
- LOW — minor defect or polish.

## Workflow

Detected → Reproduced → Classified → Assigned → Fixed → Tested → Verified → Closed.

## Required fields

- BUG-ID
- Date
- Component
- Severity
- Description
- Reproduction steps
- Expected result
- Actual result
- Root cause
- Correction
- Regression test
- Commit/PR
- Verification
- Status

## Rule

No anomaly is closed only because code was changed. A regression test and verification evidence are required.
